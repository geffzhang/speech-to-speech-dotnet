## D023：函数调用的输出项生命周期补齐

### 上游口径（handlers/response.py）

- 每个工具调用三条事件：`output_item.added`（function_call item、**arguments=""、status=in_progress**）→ `function_call_arguments.done` → `output_item.done`（完整 item）。
- `_output_part_context(conn_id, kind)`：连续文本共享一项；**每个调用各开新项**；调用后的文本再开新项。下标按到达顺序递增。
- 终态 `output[]` = 文本项 + 调用项按 output_index 合并排序（`_build_output_items`）；item 本身**不带 index 字段**，顺序即下标。
- 收口时「显式 in_progress 的调用」补发 output_item.done（`finished_function_call_indices` 之外）。

### 本实现改动

- `ServerEvent`：新增 `FunctionCallItem` / `FunctionCallOutputItemAdded` / `FunctionCallOutputItemDone`；`FunctionCallArgumentsDone` 与全部音频/转写 delta 事件加 `output_index` 参数。
- `RealtimeConnection`：输出项状态机（`_nextOutputIndex` / `_currentOutputKind`）+ `PendingTextOutput` 列表替代单一 `_assistantItemId`/`_assistantTranscript`；收尾按已开启文本项逐项展开；新纯函数 `Protocol/ResponseOutput.Merge` 做混合排序（可单测，`BuildResponse` 原样保序）。
- 工具分支补代际丢弃闸门（之前没有——打断后迟到的调用会发给客户端）。

### 语料

- 协议 +3 条：`function-call-output-item-added` / `function-call-output-item-done` / `response-done-mixed-output`。
- 坑：官方 openai 模型的 function_call item 有 `object` 字段但默认 None、probe `exclude_none` 剔除——input 里必须显式给 `"object": "realtime.item"`（上游 emit 显式传了）。message item 的语料之前恰好传了所以没踩过。
- 旧 5 条 audio/arguments 语料 input 补 `output_index:0`，基线 `--update` 由官方模型全量重录。

## 声纹后端（D033 收口 —— 分离链路补齐最后一环）

**定位**：D033 之前 `ISpeakerEmbedding` 只有接缝，`--diarization` 只给活动区间、不给 speaker 标签。参照实现（voxa）这一层是空的，所以**口径不是从它那儿来的**，而是取自 sherpa-onnx（`SpeakerEmbeddingExtractor` + `FeatureExtractorConfig`）——这样能直接吃它发布的权重，不自造「差不多」的前端。

**新包 `src/SpeechToSpeech.Backends.SpeakerEmbedding`**：
- `KaldiFbank`：80 维 log-mel。25ms/10ms、**povey** 窗、预加重 0.97、**去直流之后**再预加重、**`snip_edges=false`**（帧中心对齐 + 边界**单边镜像** `−1→0`/`n→n−1`）、512 点 FFT、80 个 kaldi 三角 mel（20 Hz~Nyquist−400、自然对数 `1127·ln(1+f/700)`、不归一化）、log 前按 **`FLT_EPSILON`=1.1920929e-7** 截断、`global-mean` 逐维减时间均值。
  - **最大的坑**：`float.Epsilon` 是 1.4e-45（反规格化最小值），跟 `FLT_EPSILON` 差 38 个数量级；用错会让数字静音的帧从 −15.94 变成 −103，不抛任何异常。
- `OnnxSpeakerEmbedding`：metadata 读 `framework/sample_rate/output_dim/normalize_samples/feature_normalize_type`；输出 L2 单位化；采样率**不做内部重采样**（接缝两边都是 16k，管线已重采样，再塞一套会让两种口径悄悄分叉）。
- 模型：3D-Speaker CAM++（中英通用），28,281,164 B，SHA-256 `aa3cfc16…`，`models/speaker-embedding/model.onnx`（不入库）。输入 `x:[N,T,80]` 动态 T，输出 192 维。

**对拍**（这才是硬证据，不是「跑起来了」）：
- `kaldi-native-fbank` 同参数生成参照矩阵（3s 真实语音 300×80）：逐元素最大差 **1.8e-4**，且全部落在能量接近 floor 的低频 bin（log 在 1e-7 能量上对 float 舍入极敏感）——是精度不是口径。
- knf + onnxruntime 跑同一权重 vs C#：端到端 embedding **余弦 > 0.9999**。
- 定点值用**合成信号**固化进 `KaldiFbankTests`（参照由同参数生成），不需要音频素材入库。
- 阈值实测（英语 Gatsby + 西语 es-ES 交替 18.7s）：同人距离 **0.14–0.29**、异人 **0.71–0.84**；`MatchThreshold=0.45`/`NewSpeakerThreshold=0.62` 落在中间，不是贴数据调的。

**三处真缺陷（全是「替身全绿、真权重必现」，共同表现=整场只剩一个说话人）**：
1. **声纹夹带后续音频**：`EmbedSpan` 把只增不减的 scratch **整块**交给 `CopyTo`，而 `CopyTo` 按**目标长度**复制 → 先 6s 后 0.6s 时短的连着上一段残留一起算。所有向量朝「整条音轨平均」收敛。修：传本段长度。回归 `An_embedding_sees_only_its_own_turn`。
2. **同一轮次被反复认领**：`Associate` 只在 `turn.StartFrame == 0` 时查通道映射，起点落在 own 区中间时只查 `_open`——而那段早已 `Finalize` 移出。窗口 10s/跳 1s ⇒ 一段 3s 的话被反复建新段（18.7s 音频切 14 段、**段总时长 31s > 音频本身**）。修：不论起点在哪都先按通道映射认亲。
3. **凹陷判据在真实概率上永不成立（C036）**：参照要求概率掉到 `0.7×onset=0.35` 以下才计静音，而真实 pyannote 换人处给约 **0.40** 的持续弱响应——既低于 onset 又高于 offset，凹陷永不成立，两人的话被缝成一段，声纹取到混合声后连锁塌成 1 个说话人。修：**删掉 `Offset`**，凹陷只按 `Onset` 判定。宁可多切几段（同人相邻段共享标签，对外无损）。

**修复后真跑**：speakers=**2**；speaker_0 = 0.03-3.69 / 7.05-10.51 / 14.12-17.26，speaker_1 = 4.05-6.36 / 11.19-13.43 —— 与素材 A/B 交替逐段吻合。声纹 15 次调用 / 14 个段（随轮次不随窗口）。

**CLI/装配**：`--speaker_embedding_model`（或 `SPEECH_TO_SPEECH_SPEAKER_EMBEDDING_MODEL`，默认 `models/speaker-embedding/model.onnx`）；`DiarizationOptions.Validate` 在启用分离时要求它，缺模型**启动即失败**（不退化成无标签静默运行）。探针加 `--embedding` / `--probs` / `tracks` / `segments` / `speakers_detail`。
