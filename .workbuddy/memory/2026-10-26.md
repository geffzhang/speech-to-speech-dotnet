## 协议层差分语料（同上，第二轮）

### 关键发现：基线不用起服务就能录

上游 `RealtimeService` 的 handler 全是 **`(conn_id, event) -> list[ServerEvent]`** 的纯函数，
`RealtimeService(text_prompt_queue=Queue(), should_listen=Event())` 直接可实例化，
**不需要模型、不需要 FastAPI、不需要网络**。`svc.response._build_response(cid, status)` 也能直接调。

代价是装依赖：`openai==2.28.0`（与上游 pyproject 锁定一致）+ `numpy` + `scipy` + `starlette`。
`scipy` 那次 pip 报 502 但 import 却通过了——说明它只在某条可选路径上，别被这报错误导。

### 两个真实缺陷（重点）

**1. JSON 序列化把中文和 base64 特殊字符转义了（C012，已修）**

本实现原先 `new JsonSerializerOptions { WriteIndented = false }` —— 默认 `JavaScriptEncoder`。
实测 `"你好，世界 +/="` 上线成了 `"\u4F60\u597D\uFF0C\u4E16\u754C \u002B/="`：
汉字 3 字节变 6 字节（**中文载荷体积翻倍**），base64 里的 `+` 变 `\u002B`。

上游 `transports.py` 走 Starlette 的 `ws.send_json`，其源码是
`json.dumps(data, separators=(",", ":"), ensure_ascii=False)` —— **不转义**。

修法：`Encoder = JavaScriptEncoder.UnsafeRelaxedJsonEscaping`。
顺带把探针改成调用 `ServerEvent.Serialize`，否则探针自己 `ToJsonString()` 就测不到产品路径。

（`websocket_router.py:709` 另有一处 `model_dump_json()`，pydantic 默认也不转义，两条路径一致。）

**2. 服务端事件只覆盖 16/26（D013）**

`tools/refprobe/protocol_coverage.py` 反射上游 `ServerEvent` 联合类型，与本实现 `EventNames` 对比：
覆盖 61%。缺的 9 类里最要命的是 `response.output_item.added` / `response.content_part.added` ——
**OpenAI 官方客户端靠这两类建立消息项与内容片，缺了整段回复可能渲染不出来**。

其余缺口：`transcription.completed` 缺 `usage`（官方 schema **必填**，D011）；
`response` 对象缺 `usage`/`output_modalities`/`conversation_id`（D012）；
`conversation.item.created` 的 item 缺 `content` 数组与 `previous_item_id`（D014）。

### 工具链

- `tools/refprobe/schema_dump.py` —— 导出官方 `openai 2.28.0` 的 **46 种**服务端事件及必填字段。
  坑：`RealtimeServerEvent` 是 `Annotated[Union[...], PropertyInfo(discriminator='type')]`，
  要**先拆一层 Annotated** 才能 `typing.get_args` 到模型类；联合里还混着非模型成员，要 `hasattr(model_fields)` 过滤。
- `tools/refprobe/protocol_coverage.py` —— 事件级覆盖审计。默认 `--python` 指向 venv，
  因为反射上游要真的 `import` 上游模块。
- `tools/ProtocolProbe`（C#）—— 按 `event` 名 switch 到工厂；未实现的事件以退出码 3 报出，不伪造输出。
- `corpus/protocol/` 12 条，两侧 event_id 归一化为 `"<event_id>"`，其余逐字节比。

### 语料只收「已对齐」的

9 类取 12 条（含中文与含 `+/` 的 base64），全绿进 CI。结构有差异的 7 类**不进语料** ——
否则 CI 长期标红就失去意义。缺口由 coverage/schema_dump 两个审计承担，结论写进 D011–D014。

## 回合续（13:00–14:00）收尾三件事：终态语义、C015、D011

### `status_details.type` 必须与 `status` 同域（C015）

原先工厂里 `status_details.type` 是硬编码 `"incomplete"`，取消时就产出
`{type: incomplete, reason: client_cancelled}` —— 官方 schema 里不存在这个组合，
按判别器解析的客户端会拒收或误判。改为 `type = status`：
`completed` 不发 `status_details`；`cancelled`/`incomplete`/`failed` 各发同名 type，
`failed` 额外带 `error.code`/`error.message`。

### 协议语料补到 32 条

- 终态三条：`response-done-cancelled` / `-incomplete` / `-failed`
- `transcription-completed`（D011 修复后才可入语料）

新坑：`response.done` 的上游入参是**完整 response 对象**（`{"response": {...}}`），
不是散字段。`ProtocolProbe` 因此加了 `ResponseObject()` / `RespText()` / `StatusDetails()`
三层读取（与 `error` 的处理同构），平铺写法留作兼容。
另一个坑：官方 `RealtimeResponse.output` 是 `Optional`，不传就 `exclude_none` 掉，
而本实现恒发 `output: []` —— 语料入参必须显式给 `output: []` 才可比。

### D011 转写完成的 `usage` 是必填

`conversation.item.input_audio_transcription.completed` 的 `usage` 在官方 schema 里
**必填**（`duration` / `tokens` 二选一），缺了是整条事件被拒收，不是「少个统计」。
上游报 `{type: "duration", seconds}`，秒数取该输入项的 VAD 段时长：
在 `speech_stopped` 时记下 `SpeechStoppedEvent.DurationSeconds`，转写完**立即归零**
（否则下一轮不走 VAD 的路径会继承上一轮数字）。

### D012 不能当独立小任务（重要结论）

上游 `usage` 不是「把计数塞进去」：`pending_token_usage` 按 `response_key` 记账，
只有被确认的响应才 `_apply_pending_token_usage` 结转，被取消/丢弃的响应直接 `pop`。
这套「按响应键记账 + 丢弃」与 C006 投机轮次的 HOLD/grace 是**同一套状态机**。
先补 D012 会在打断场景产出错误计费 —— 所以顺序是 **C006 在前，D012 随后**。
已能独立补的 `output_modalities` / `audio.voice` / `output` 数组也留到与 usage 一并做，
避免载荷出现「有模态没用量」的半截状态。
