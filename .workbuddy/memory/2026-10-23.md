## 后续：接入 NAudio 作为音频参考库

用户给出 `C:\workshop\github\NAudio`（音频参考库）。本地仓库在 `54cb8188`，`VersionPrefix` 3.3.1（未发布），NuGet 最新正式版 3.3.0。

### 做了什么

1. **NAudio 2.2.1 → 3.3.0**，并加 `NAudio.Alsa 3.3.0`。升级后暴露 4 类破坏：
   - `WaveOutEvent` → `WaveOut`、`WaveInEvent` → `WaveIn`（改名 + 标记过时）
   - `BufferedWaveProvider.BufferDuration` 由可写变只读，改从构造函数传 `TimeSpan?`
   - `WaveOut.DesiredLatency` 被移除，只剩 `NumberOfBuffers`
   - WinMM 全部类型加 `[SupportedOSPlatform("windows")]`，未加 OS 守卫会报 CA1416
2. **新增 `src/SpeechToSpeech.Cli/Audio/AudioDevices.cs`**：`IAudioDeviceSet` 抽象 + 三平台实现。
   - Windows：`WasapiPlayerBuilder`（共享模式 + 事件同步 + 120ms）播放，`WaveIn` 录制
   - Linux：`AlsaIn` / `AlsaOut`（命名空间 `NAudio.Wave.Alsa`）
   - macOS：不接入，`NAudio.MacOS` 只有 `3.3.0-preview.34`，启动时抛 `PlatformNotSupportedException`
3. **修了一个真实并发缺陷**：原 `AudioClient` 把 `async` 发送写在 `DataAvailable` 回调里，而 `ClientWebSocket` 不允许并发 `Send`。改为有界 `Channel<byte[]>`（容量 64、满则丢最旧）+ 单消费者做重采样与上行，另加 `SemaphoreSlim` 兜住 `Send`。
4. `talk` 连接失败不再抛调用栈，改为一行可读错误。

### 关键约束（改代码前必看）

- **`WasapiRecorder` 没有实现 `IWaveIn`**（只有同形方法），无法与 `AlsaIn` 共用抽象，所以录制留在 `WaveIn`；播放侧 `WasapiPlayer` 实现了 `IWavePlayer`，所以能换。**Windows 因此同时用了 WASAPI 和 WinMM 两套 API**（已登记 C010）。
- `NAudio.Alsa` 不在元包里（无 `net9.0-linux` TFM），必须显式引用。运行需 `libasound.so.2`。
- macOS 要走通，等 `NAudio.MacOS` 出正式版后实现 `MacAudioDevices`，接 `CoreAudioRecorder` / `CoreAudioPlayer`。

### 待确认的一个优化点（未擅自改）

客户端上行声明 24 kHz，实际是 16 kHz 采集后上采样。服务端 `RuntimeConfig.InputSampleRate` 会读 `session.update` 里声明的 rate，所以**完全可以声明 16 kHz**，省掉 16k→24k→16k 的往返重采样与 50% 带宽。但这是线上行为变更，需 geff 拍板。
